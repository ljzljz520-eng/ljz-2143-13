# 背景窗口控件管理 · 设计文档

> 范围：把现有 SDL2 背景窗口的**标题与「开始 / 设置 / 退出」三个按钮**纳入统一
> 控件管理；网页端编辑标题、字号与布局；服务器做**可用区域校验并落库**；
> C 客户端执行**带版本的命令**；并约束浅/深背景、自适应暗化、字体回退、
> 触摸命中、焦点顺序、按钮四态、断网策略、受控退出与崩溃后恢复。

## 1. 架构总览

```text
┌────────────────────┐   草稿/发布/冲突    ┌─────────────────────────┐
│ 网页编辑器          │ ───────────────────▶ │ Python 服务器            │
│ web/index.html      │ ◇ 409 草稿冲突       │ server/server.py         │
│ (标题/字号/布局)    │ ◇ 422 可用区域校验   │ SQLite (schema.sql)      │
└────────────────────┘                     │ 布局版本 / 任务 / 日志    │
                                            └───────────┬─────────────┘
        轮询 /layout、/policy、POST /commands、/journal  │ HTTPS(部署)
                                            ┌───────────▼─────────────┐
┌──────────────────────────────────────────▶│ C 客户端 (SDL2 + core)   │
│  src/core/*.c  （不依赖 SDL，宿主可测）     │  控件管理 / 渲染 / 输入   │
│  layout · command · fsm · policy           │  退出协调 / 本地日志       │
│  exit · journal                            └──────────────────────────┘
└────────────────────────────────────────────
```

* **内核与表现分离**：`src/core/vw*.c` 是纯 C11、无 SDL 依赖的确定性逻辑，
  在开发机上直接 `make check` 编译运行；`src/widgets.c` + 现有 SDL 渲染层
  只负责把内核产物画出来、把输入喂进去。
* **同一份布局规则两处实现**：C 的 `vw_layout_compile()` 与
  Python 的 `validate_layout_spec()` 共用同一组常量与校验项
  （退出保留区、触摸 ≥44px、标题 ≤127 字节、字号 10..120、内联降级），
  并各自用**同构的 FNV-1a 规范串**得到 `spec_hash`，作为“端侧实际布局”与
  “服务端期望布局”一致性的证据。

## 2. 控件模型与“控件管理”

每个控件（`VwWidget`）由控件管理器统一登记，包含：

| 字段 | 含义 |
|---|---|
| `id` | `title / start / settings / exit` |
| `visual` 矩形 | 实际绘制区域 |
| `hit` 矩形 | 指针/触摸命中区域；**任何两个 hit 矩形不重叠** |
| `tab_index` | 键盘 Tab 焦点顺序，**与布局同源计算** |
| `enabled` | 可用性（服务器策略 + 本地策略合并后决定） |

标题是**非交互**信息控件（不命中、不进 Tab 环）；三个按钮均在管理器中。
管理器同时拥有：版本化命令抓取器（capture）、按钮状态机、策略决策器、
退出协调器、日志句柄。渲染层不自行摆放任何控件，只消费 `VwLayoutArtifact`。

## 3. 网页编辑与可用区域校验

网页（单文件 `web/index.html`）可编辑：**标题、字号、开始/设置的布局**
（`inline` 标题栏内联；`split` 底部操作栏）。另显示：

* 设备**实际布局**（轮询 `/layout`，含版本号与 spec_hash）；
* **草稿冲突**：另一控制台更新后，保存返回 `409` 并展示服务器草稿，
  提供「载入服务器版本（rebase）」；
* **未完成操作恢复记录**：设备上报的 pending/done/failed 列表。

服务端校验（`validate_layout_spec`，与 C 端同规则）：

1. 标题非空、合法 UTF-8、**1..127 字节**；
2. 字号 **10..120px**；
3. 退出固定右上角，尺寸 `clamp(font+18,36,72)`，其左侧 8px 为永久保留带；
   标题可用宽度 `< 2*font` 即拒绝（“小屏配大字”不可用）；
4. `inline` 时，标题栏保留带宽度不足以并排放两个 ≥2×44px 的按钮，
   **拒绝并建议 split**；C 端在运行时也会因拥挤自动降级为底部操作栏，
   保证“长标题不盖住退出入口”；
5. `split` 时，底部操作栏高度不得侵占屏幕；
6. 设备最小触摸目标不得低于 **44px**。

校验通过才写 `drafts`；发布时再次校验并写 `layouts`，版本号单调递增。

## 4. 数据库模型（`server/schema.sql`）

`devices`（设备几何/在线）、`drafts`（编辑器草稿，含单调修订号 `rev` 与
`base_version`）、`layouts`（已发布布局 `(device,version)` 唯一）、
`commands`（带幂等键与版本的命令审计）、`tasks`（`idempotency_key UNIQUE`，
幂等任务）、`device_journal`（端侧未完成操作恢复记录）、`policy_cache`
（服务器可用性决策）。

## 5. 版本化命令协议（C 客户端执行）

按下时，抓取器记录 `(控件, 当时 artifact.version, 坐标, pointer_id)`；
抬起时只有同时满足以下条件才发出命令：

* 仍在**同一控件**的 hit 区内；
* **当前布局版本与按下时一致**（版本换版则该次交互取消，不发命令）；
* 控件此刻仍 `enabled`。

命令信封（`vw_command_serialize`）：

```json
{"v":1,"widget":"start","layout_version":12,"spec_hash":437059567,"x":803,"y":640}
```

服务端 `/commands` 比对设备最新布局版本：不一致返回 `409 current_version`，
客户端随后拉取新版并原子替换场景（纵深防御：即使抓取器漏判，服务端也拒）。

## 6. 实际布局规则（必须落到真实布局里）

实现见 `vw_layout_compile()`：

1. **浅/深背景与自适应暗化**：由渲染层采样背景亮度 `L(0..255)` 输入编译器。
   `L<64`（深背景）用很轻的遮罩（标题 28/操作栏 20 alpha）；
   亮背景 `title=40+L*3/5`、`action=30+L/2`，保证浅色按钮文字对比度。
   文案统一浅色，暗化随背景强度自适应。
2. **字体回退**：字体链按序探测，第一个可用族生效；首选缺失则
   `font_status=FALLBACK` 并记录实际族；全部缺失则 `MISSING`，仍以合成度量
   完成布局（不让界面“无字体即崩”）。UTF-8 非法字节计入 `missing_glyph_count`。
3. **长标题**：按码点（非字节）截断并加省略号“…”，预算包含省略号宽度；
   标题 clip 的右边界 = 退出区左边界 − 8px，**结构上不可能盖住退出**。
4. **触摸命中**：命中区向中心扩张到 ≥ `min_touch`；退出区可额外外扩
   （`exit_hit_grow`），其它控件若与之相交则从右侧**削让**，最终断言
   “任意两 hit 矩形不重叠”；hit 判定时**退出优先**。
5. **键盘焦点序**：按视觉 `(y,x)` 排序得到 开始→设置，退出固定为 Tab 环最后
   一项（误触代价最高，不抢占首个焦点）。焦点序与几何在**同一编译器输出**里，
   布局换版时二者原子更新。

## 7. 按钮四态与“超时重按不得双开”

状态机（`vw_fsm.c`）：`idle → executing → confirming → success/failed`
（含自动 `reset`）。

* `idle` 按下：生成幂等键 `d<device>-s<session>-p<pressSeq>`，进入
  `executing`，登记单飞（single-flight）记录并请求服务器；
* 服务器 `ACK`：进入 `confirming`（任务在跑），**此时再按直接忽略**；
* **网络超时**：任务“可能已在服务器创建”。转入 `confirming` 并把飞行记录
  标为“结果未知”、**保留同一幂等键**；此时重按是**安全重试**——服务端
  `tasks.idempotency_key UNIQUE`，同键返回同一 `task_id`，**物理上无法产生
  两份任务**；
* `success` 后重按忽略直到 `reset`；`failed` 后重按才分配**新**幂等键。

服务器侧 `/tasks`：同键首次 `201`，重复 `200 idempotent_replay=true`，
返回同一任务。双重保险 = 客户端单飞 + 服务端唯一约束。

## 8. 服务器可用性 vs 终端本地策略（断网动作范围）

`vw_policy_decide(action, net, server, local)`，**deny 优先**：

| 动作 | 在线·有服务器决策 | 断网 / 服务器不可达 |
|---|---|---|
| 开始 | 依服务器标志 | 允许，但仅当本地无正在运行任务；动作写日志，联网补传 |
| 设置 | 依服务器标志 | 仅当本地有**有效缓存配置**时允许，否则拒绝 |
| 退出 | 始终允许（服务器不能禁用退出） | **始终允许**，走受控退出路径 |

决策结果带 `decided_locally` 与 `reason`，便于审计“这是服务器判定还是终端
兜底”。

## 9. 退出协调（业务确认 + 渲染资源释放）

`idle → saving → flushing → releasing → done`：

1. **saving**：等待业务确认保存（回调），预算 5s；
2. **flushing**：尝试把本地日志/结果同步服务器一次（预算 3s）。
   **服务不可达也继续**——磁盘日志即持久恢复记录，`flush_code!=0` 不阻塞退出；
3. **releasing**：释放渲染资源（纹理、字体），本地必做；
4. 长任务期间用户**第二次按退出** = `forced`：跳过等待，带着未完成记录
   受控退出；释放阶段仍保证执行。

## 10. 恢复记录（journal）

行式追加日志 `key|action|task_id|status`，同键多条按**最后状态**归并。
启动时 `vw_journal_replay` 统计 pending/done/failed，pending 项：
能在线则幂等补提（同键不重复），不能在线则继续挂起并在 UI/网页展示。
强制退出（服务不可达）后重启，仍能看到上次未完成操作——对应验收
“未完成操作的恢复记录”。

## 11. 并发放心清单

* 两个控制台同时改标题 → 草稿 `rev` 乐观锁，后保存者收 `409` + 服务器草稿；
  发布时再对 `base_version` 做一道发布冲突（设备实际布局可能已变）。
* 按下到抬起之间换版 → 抓取器取消；服务端版本校验 409；场景原子替换。
* 超时重按 → 同幂等键，单飞 + 数据库唯一约束。
* 长任务期间退出 → 二次按强制受控退出，资源释放与日志保全。
